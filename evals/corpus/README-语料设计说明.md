# 知识库 B · 森屿家居（自造中文语料）

> 状态：**当前有效** ｜ 建立 2026-10-17

> 题集：`repo\evals\questions\{retrieval,generation,refusal,adversarial}.yaml`

## 这是什么

**知识库 B** 是给评测用的人造语料：一家**虚构**的跨境家居公司「森屿家居 / Senyu Home」
的对外政策文档、存档、兄弟品牌档案与内部材料。

**为什么必须自造**（这是项目的核心约定之一）：

知识库 A 是 FastAPI 官方文档 —— 大模型**训练数据里本来就有**。
检索到没检索到，它都能答对 ⟹ 拿 A 库的分数当成绩是**自欺**，
面试官一句"这题不用 RAG 也能答"就能把它问穿。

B 库是**模型没见过的**内容：答对必须真的依赖检索。这才是"检索有效"的证据。

## 为什么是"核心条款 ＋ 大量干扰"，不是"就写 20 条"

```
核心条款（现行、正确）        9 篇   ← 标准答案落在这里
常识篇目（现行、真像企业库）  12 篇   ← 2026-10-27 W22 加的（见下节）
对照/干扰（像、但不对/不适用） 27 篇   ← 让检索有分辨力
──────────────────────────────────
总量                         48 篇 → **314 个 chunk**（2026-10-27 实测）
```

**检索难，难在干扰项，不在库大。** 如果库里只有 20 条正确答案，
"检索几乎必中"，那时测到的只是**生成质量**；而本项目的深度锚是**检索质量**。

## 2026-10-27 加的 12 篇"常识篇目"（W22 · D10）

**动机**：原来的 36 篇里，"干扰"全是**结构化的**（历史版本 / 兄弟品牌 / 未生效草案 / 内部稿）。
真实企业库不长这样 —— 它长的是一大堆**彼此主题相邻、而且都算现行**的日常页面。

## 题集怎么用（4 个分层文件）

| 文件 | 层 | 判什么 |
|---|---|---|
| `retrieval.yaml` | **检索层** 25 题 | `must_hit` 里的文档要出现在 top-k（k=5）引用来源里。问句**故意不含关键词** |
| `generation.yaml` | **生成层** 20 题 | `required_points` 全中 ＋ `must_cite` 至少一个命中 ＋ `must_not_say` 一条都不许出现 |
| `refusal.yaml` | **拒答层** 15 题 | 必须拒答，且**不调用生成模型**（由 `_should_refuse` 在调模型前判定） |
| `adversarial.yaml` | **抗干扰层** 10 题 | `correct` 要点要在，`wrong_source` 那个答案不许出现 |

**为什么分层**：一个错答可能出在三处 —— 没召回（检索层）、召回了但没用对（生成层）、
该说没有却编了（拒答层）。混在一起打一个总分，**改不动**。

**再加一组消融**（同一批题跑四遍）：全文-only / 向量-only / RRF / ＋rerank。
这几组数字才是"检索真的有效"的证据 —— 单靠总分说明不了任何事。

## 维护规则（**改一个数字要同步哪几处**）

以"无理由退货天数"为例 —— 改它必须同时改：

1. `10-退换货/10-退换货总则.md`（总则值）
2. `10-退换货/11-地区差异.md`（各国值 ＋ 跨地区判定示例）
3. `90-干扰-历史版本/06-版本变更公告.md`（旧值→新值对照表）
4. `94-干扰-相邻概念/02-无理由与质量问题的区别.md`（对比表里的天数）
5. `evals/questions/*.yaml` 里所有引用该数字的题（`must_not_say` 尤其容易漏）
6. 本 README 的「权威事实表」

📌 **新增条款时不要动 `must_not_say` 的语义** —— 那个字段专门锁"典型错答"，
  一改就等于把测试放宽了。要放宽，另开一题。
