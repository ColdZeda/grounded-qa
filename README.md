# grounded-qa

> 状态：**v1.0 开发中**（后端主链路 ＋ 客服工作台前端已跑通，**67 测试全绿**）｜ 最后更新 2026-10-16

**多租户知识库问答平台** —— 客服是它的第一个业务场景。
深度锚是**检索质量与幻觉治理**：混合检索（全文 + 向量 → RRF 融合 → API 精排）、
带引用溯源的生成、低置信度**拒答**，以及一套**闭卷/开卷对照**的评测体系。

> **它解决什么问题**：把企业私有文档变成"能问、能答、答错能查证"的问答服务。
> 公开文档上 RAG 的增益其实有限（模型参数化记忆已覆盖），
> 真正的价值集中在**私有 / 长尾 / 版本敏感**的知识上 —— 这个项目会把这个结论**如实报出来**，不粉饰。

## 它是什么

一个可以**真正部署上线**的多租户知识库问答服务，面向企业客服场景：

| 能力 | 说明 |
|---|---|
| **多租户隔离** | 所有业务表带 `tenant_id`；查询统一走**强制注入租户条件的仓储层**，写入侧连客户端传 `tenant_id` 都直接报错 |
| **登录鉴权** | JWT（HS256）· bcrypt 密码哈希 · 管理员 / 成员两种角色 · 登录接口对"密码错"和"用户不存在"返回**完全相同**的响应 |
| **混合检索** | PostgreSQL 全文检索 + pgvector 向量检索，用 **RRF** 融合，再走 API 精排 |
| **引用溯源** | 回答附带原文出处（落库到 `messages.citations`），可点开核对，而不是"信我" |
| **低置信拒答** | 检索不到 / 分数低于阈值时**明说不知道**，不编；拒答单独打标（`messages.refused`），**可被统计** |
| **文档入库** | 上传 → Redis 队列 → 后台 worker 解析/切分/向量化（不阻塞请求） |
| **可观测** | `/healthz` ＋ `/metrics`（Prometheus 格式）＋ **三道启动自检**（中文全文检索 / 拒答阈值与模型配套 / 向量元数据）；**自研看板与告警属于 v1.1，尚未做** |
| **评测体系** | 闭卷（关 RAG）/ 开卷（开 RAG）对照，双知识库，badcase 归因 |

**安全红线**：**服务端不执行任何用户提交的代码或命令。** 所有模型调用走外部 API，不在服务器上跑本地模型。

## 接口一览

统一前缀 `/api/v1`（前缀来自配置，不写死）。除登录外都要 `Authorization: Bearer <token>`。

| 方法 | 路径 | 说明 |
|---|---|---|
| `POST` | `/auth/login` | 表单登录 → JWT（**"密码错"与"用户不存在"返回完全相同**的响应与耗时） |
| `GET` | `/auth/me` | 当前用户（角色 / 租户） |
| `GET` / `POST` | `/conversations` | 会话列表 / 新建（**懒创建**：会话在第一次提问时才真正建） |
| `GET` | `/conversations/{id}/messages` | 消息列表（刷新页面后恢复上下文） |
| `POST` | `/conversations/{id}/messages` | **提问 —— SSE 流式**：`sources` → `delta`* → `done`，出错发 `error` |
| `POST` | `/documents` | 知识库上传（**仅管理员**，只吃 `.md`/`.markdown`/`.txt`）→ **202** 已接受、异步入库 |
| `GET` | `/documents` | 文档列表（带 `status` / `error_message`，界面靠它轮询） |
| `GET` | `/reports` | **只读**评测报告（**只给聚合数字**，不吐逐题明细） |
| `GET` | `/usage/me` | 我今天的 token 用量 / 配额 / 限流（读 Redis 记账；**取不到返回 `null`，不是 0**） |
| `GET` | `/usage/tenant` | **租户内**成员的今日用量（仅管理员，看不到别的租户） |
| `GET` | `/monitoring/snapshot` | 运维看板（仅管理员；**服务端代查** Prometheus，客户端传不了 PromQL） |
| `GET` | `/admin/tenant` · `/admin/users` | 租户内管理端（**不是跨租户超管**） |
| `GET` | `/healthz` · `/metrics` | 运维端点（前者给 compose/CI 判活，后者给 Prometheus） |

**两个会被客户端撞到的约定**：

- **429** 带 `code` / `scope` / `used` / `limit` / `retry_after_s` ＋ 标准 `Retry-After` 头 ——
  前端照着退避即可，**不要立刻重试**（那只会把限流刷得更狠）。
- **越权一律 404**（不是 403）：403 等于承认"这条数据存在"，可被用来枚举有效 id。

## 架构

```
                    ┌──────────────────────────────┐
   访客 / 工作台 ──▶ │  nginx :8080                 │
                    │  反代 · 限流 · 静态缓存 · SSE 不缓冲 │
                    └──────────────┬───────────────┘
                                   ▼
                    ┌──────────────────────────────┐
                    │  自研 API（FastAPI）          │
                    │  意图路由 → 混合检索 → 精排    │
                    │  → 生成（引用溯源 + 拒答）      │
                    │  SSE 流式返回                 │
                    └───┬───────────────┬──────────┘
                        ▼               ▼
            ┌────────────────┐  ┌──────────────┐
            │ PostgreSQL 16  │  │   Redis      │
            │  + pgvector    │  │ 语义缓存+队列  │
            └───────┬────────┘  └──────┬───────┘
                    ▲                  ▼
                    │        ┌────────────────────┐
                    └────────│ 自研 mini worker    │
                             │ 解析/切分/向量化      │
                             └─────────┬──────────┘
                                       ▼
                            外部 API（对话 / embedding / rerank）
```

**两条设计原则**：

1. **一套知识库、一套向量库、一套 embedding 配置**（换 embedding 模型必须全量重嵌入，否则检索质量会静默变差）；
2. **自研核心对外暴露 OpenAI 兼容接口** → 网页 / 飞书 / 任何客户端零成本接入。

## 设计取舍一览

**这张表是这个项目的"金句集"**：每条只有「**一句话结论 ＋ 关键数字 ＋ 去哪看**」。

> ⚠️ **详细解释一律在 [`docs/architecture.md`](docs/architecture.md)，这里刻意不抄** ——
> 同一件事写两遍，两份迟早不一致，而**不一致的那一份会被人当真**。

| 结论（一句话） | 关键数字 / 证据 | 详见 |
|---|---|---|
| **拒答在调模型之前就判完了** —— 由确定性代码决定，**不问模型** | 拒答**一个 token 都不花**；拒答率**可统计、可优化**（不会变成"模型心情的副产品"） | §5.2 |
| **置信度阈值只能挂在 rerank 分数或向量余弦上** | RRF 是**名次**的函数：库里只有一条不相关内容时它照样排第一 → 拿它比阈值 ＝ **永远不拒答** | §5.3 |
| **拒答阈值 0.60 是实测标出来的，不是拍的** | 20 条样本：相关 **0.786~0.990** ／ 无关 **0.009~0.466** —— **完全分离**，中间空了 0.32 | §5.3 |
| **换 rerank 模型或换语料 → 阈值必须重标**，应用**启动时自检**这一对 | 旧值 0.35 是照 `gte-rerank-v2` 定的，而那个模型同批**最高才 0.17** → 「gte ＋ 0.35」会**全拒答** | §5.3 · §10.3 |
| **两条检索路的「失败模式」不同，所以两条都要留** | 向量强在语义、弱在**错误码 / 型号**；而客服场景**大量正是后者** | §4.1 |
| **RRF 只用名次，不用分数** | 两种分数**量纲根本不同**，各配一个权重就是拍脑袋；`k=60` 用来**压平头部** | §4.2 |
| **中文全文检索曾经"静默全失效"** | `ctype=C` → `show_trgm('退款政策')` 返回**空集**、相似度**恒为 0**；`C.UTF-8` → **0.4**。<br>⚠️ 而接口**不报错、状态码 200** | §4.4 |
| **「混合检索比纯向量好多少」只有中文语料答得了** | 在英文语料上做消融，三组结果**几乎一样** —— 因为全文路**根本没参与**。这不是"数据不好看"，是**实验设计上就测不到** | §4.7 |
| **多租户隔离"焊死"在仓储层** | 你**没有"忘记加 `WHERE tenant_id`"这个选项**；越权一律 **404**（403 等于承认"这条数据存在"，可被用来枚举） | §2.2 · §2.5 |
| **"密码错"和"用户不存在"返回完全相同的响应** | 而且**耗时也抹平**（用户不存在也照样跑一次哈希）→ 不可用来枚举账号 | §3.4 · §3.5 |
| **JWT 里带了租户 id，但每个请求仍然回库核对** | 否则"人已经离开这个租户，旧 token 还能读它的数据" | §3.6 |
| **「详细程度」开关：藏的是分数，不是来源** | 数据层**永远存全**（**拒答也落** `citations` ＋ `confidence`）；分档只发生在界面层 | §9.19 |
| **SSE 用手写切帧，不用 `EventSource`** | `EventSource` **只能发 GET**；而且帧会被网络切开、**一个汉字会被切成两半** | §9.12 |
| **不用 Celery** | 单机低频批处理，**约 40 行 `BLPOP` 循环**就够；重型框架的运维成本 > 收益 | §10.1 |
| **不用独立的向量库**（Milvus / Qdrant / Chroma / FAISS） | 多租户过滤和向量检索能写在**同一个 `WHERE`** 里，没有跨库一致性问题；也少一个容器 | §10.1 |
| **"不做 HTTPS"是决定，不是遗漏** | 飞书走**长连接（出站）**，本就不需要证书和公网回调 | §10.2 |
| **2C2G 上每个容器都有 `mem_limit`** | 容器预算 **≈ 670 MB ／ 可用 ≈ 1.2 GiB** | 计划书 §2.3 |
| **上传拆成「建行 → 排队 → 处理」三段** | 请求路径上**不碰 embedding**（秒级、会失败）；字节落共享卷、消息里只有 UUID —— 否则一个 1 MB 文件 base64 后 1.3 MB，Redis 淘汰时会**静默丢消息**（表现：上传成功、永远 pending） | §9.26 |
| **限流与配额是两把尺子** | 次数/分钟治「刷」，token/天治「烧钱」；后者是**软熔断**（流式没法中途掐断：这次跑完记账、下次才拒） | §9.27 |
| **Redis 挂了就放行**（fail-open） | 这两把尺子治**成本**、不治安全；缓存抖一下就整站 429，等于把「缓存故障」升级成「服务不可用」。但**放行必须留痕**（`gq_limit_failopen_total`）—— 静默放行才是真问题 | §9.27 |
| **embedding 元数据锁：读侧只比「同一个模型」的向量** | 换过模型后新旧向量**不在一个空间**，余弦相似度**是噪音不是相似度**；而它不报错、不崩溃、只是答案慢慢变差。读侧硬过滤把「不可比」变成「不存在」 | §9.28 |
| **已知的将就也一并写出来** | 例：`citations` 字段**混装两种含义**（引用 / 检索候选）—— **字段名会撒谎** | §10.3 |
| **看板自己画，不引 Grafana** | 2C2G 上少一个 ~100 MB 的进程；代价是**没有历史回看 / 没有告警静默**。Prometheus 的 9090 **不发布到宿主机**，看板由 API **代查**（客户端传不了 PromQL） | §9.29 |
| **告警也不用 Alertmanager** | Prometheus 只负责**算**，一个 60 秒的搬运工读 `/api/v1/alerts` 推群机器人。⚠️ 代价写清：**api 挂了就不推**（而那时 `ApiScrapeDown` 正好该响）<br>⚠️ 群机器人**回 HTTP 200 也可能是拒绝**（错误在 body 的 `code` 里）—— 不校验业务码就会把"没投递"记成"已投递" | §9.30 |
| **配额页不新开计量** | token 只有 `limits.py` 一个写入口，页面**只读**；**取不到显示 `—` 而不是 0**（"不知道"和"没花"是两件事）；成本只在配了单价时才算，且**单价必须一起显示** | §9.31 |
| **备份的价值只有恢复过才算数** | 每天 03:00（`systemd timer` —— 这台机 `cron` 根本没在跑），`pg_dump -Fc` 留 7 **份**（按份数不按天数）。恢复演练**连结构一起比**：只看行数会漏掉「数据都在、向量没了」 | §9.32 |
| **压测第一版结论是错的，而且是我自己量错的** | 顺序比 "pre_ping 开→关" 得到 +22%，其实是**冷启动 vs 热态**；交替测量后差异**完全消失** ⟹ 没有为性能改任何默认值 | §9.33 |

> 📌 **"故意不做"的完整清单**（K8s / Grafana / Elasticsearch / 微调 / 工单系统 …）
> → architecture **§10**。**每条都写了「为什么否掉 ＋ 什么时候该重新考虑」**。

## 设计说明（为什么这么做）

架构图只说了"是什么"。**每个不显然的决定背后的理由，单独写在一份文档里：**

### 📖 [`docs/architecture.md`](docs/architecture.md)

它回答的是这类问题：

| 你会想知道 | 文档里的答案 |
|---|---|
| 多租户隔离凭什么**不会漏**？ | 三道防线：表必须带 `tenant_id`（有元测试守着）→ 查询必须过仓储层（条件焊死在构造里）→ 写入侧不接受客户端指定归属 |
| 越权测试为什么**故意**让"另一个租户的管理员"来攻击？ | 因为"成员 A 读成员 B"是**假测试** —— 就算租户条件没写，`user_id` 过滤也会挡住 |
| 为什么**先判要不要拒答，再决定调不调模型**？ | 让模型自己判断"要不要拒答"，拒答率就成了模型心情的副产品 —— **统计不出来也优化不了** |
| 为什么 RRF 分数**不能**当拒答阈值？ | RRF 是名次的函数：库里只有一条不相关内容时它照样排第一、照样得分 → 拿它比阈值等于**永远不拒答** |
| 为什么两条检索路都要留？ | 它们的**失败模式不同**：向量强在语义，弱在错误码/型号；而客服场景恰恰大量是后者 |
| 全表扫描为什么不用索引？ | 用了函数形式（确定性更好），代价是吃不到 GIN 索引；**知道怎么改，但现在规模不值得做** |
| 哪些事是**故意不做**的？ | 文档最后一节是 **§10 不做清单**（分「技术选型 / 功能范围 / 已知不完美」三类）：K8s、Grafana、Milvus、Elasticsearch、微调、工单系统、HTTPS……**每条都写了原因 ＋ "什么时候该重新考虑"** |

> **建议的阅读顺序**：先看 `docs/architecture.md` 的 §1（一次提问经过哪些环节），
> 再挑你关心的那节。每一节都是「做法 → 为什么 → 不这样会怎样 → 代价」。

## 技术栈

| 层 | 选型 |
|---|---|
| 语言 / 后端 | Python 3.13 · FastAPI · SQLAlchemy 2（async）· Alembic |
| 数据库 | PostgreSQL 16 + pgvector |
| 缓存 / 队列 | Redis（语义缓存 + `BLPOP` 队列） |
| 异步任务 | **自研 mini worker**（约 40 行 `BLPOP` 循环，**不是 Celery**） |
| 前端 | Vue 3 + TypeScript + Vite |
| AI 框架 | LangChain 最小集 · Function Calling · MCP Server |
| 容器 | Docker + Compose（全服务 `mem_limit` + `healthcheck`） |
| 网关 | nginx（`:8080`） |
| 监控 | Prometheus + node_exporter + 自研看板 |
| CI/CD | GitHub Actions → 阿里云 ACR → SSH pull → 健康检查 → 失败自动回滚 |
| 模型 | **全部走 API**，配置按**能力**命名、不绑厂商：对话 = DeepSeek `deepseek-flash`；embedding / rerank = 百炼（随时可换） |

## 快速上手

### 前置要求

- [uv](https://docs.astral.sh/uv/)（Python 包管理）
- **Node.js ≥ 22.13** + [pnpm](https://pnpm.io/) 11.7
  > ⚠️ **不是"≥ 20"**。`web/package.json` 钉了 `packageManager: pnpm@11.7.0`，
  > 而 **pnpm 11.7 要求 Node ≥ 22.13** —— 低于它 pnpm 会直接拒绝运行，
  > 报 `This version of pnpm requires at least Node.js v22.13`。
  > 📌 这行原来写的是"≥ 20"，**2026-10-17 首次 CI 就红在这**（见 `AGENTS.md` §10）。
- Docker（本地依赖服务一律用 compose 起，**不要装到宿主机**）

### 1. 配置环境变量

```bash
cp .env.example .env
# 然后填上你自己的 API Key（.env 已被 .gitignore 忽略，绝不会进仓库）
```

### 2. 起依赖服务 + 应用

```bash
docker compose up -d          # PostgreSQL + Redis + api + worker
docker compose logs -f api    # 看日志
curl http://127.0.0.1:58000/healthz
```

> ⚠️ **本机端口规划（重要）**
> 开发机上可能同时跑着别的项目（例如 `langgraph-mcp-code-agent`，它占了 `3307` / `6379` / `8888` / `80`），
> 所以本项目把**宿主机端口**整块挪到 5 万段，避免撞车：
>
> | 服务 | 宿主机端口 | 容器内端口 |
> |---|---|---|
> | PostgreSQL | **55432** | 5432 |
> | Redis | **56379** | 6379 |
> | API | **58000** | 8000 |
>
> 从宿主机连（psql / redis-cli / GUI）用左列；容器之间互访用右列（compose 里已固定）。

### 3. 建表 + 建管理员（**首次必做**）

```bash
uv run alembic upgrade head      # 建表（含 pgvector 扩展）
uv run python -m app.db.seed     # 建默认租户 + 管理员（幂等，可重复跑）
```

> ⚠️ 这两条是**幂等**的，但 `seed` 只看 `.env` 里的 `ADMIN_EMAIL` / `ADMIN_PASSWORD`，
> 且**不会覆盖已存在用户的密码** —— 改密码是运营动作，不该被引导脚本悄悄做掉。

### 4. 本地跑后端（不开容器）

```bash
uv sync                                              # 装依赖
uv run uvicorn app.main:app --reload --port 8000     # 起服务（宿主机 8000）
```

> 接口文档在 **`/docs`**（Swagger UI）。右上角 **Authorize** 按钮可以直接用
> 邮箱 + 密码登录，然后就能在页面上调所有需要鉴权的接口。

### 5. 本地跑前端

```bash
cd web
pnpm install
pnpm dev          # http://localhost:5173 ← 注意是 localhost，不是 127.0.0.1
```

> 前端代理默认指向**容器版 API**（`127.0.0.1:58000`）。
> 若后端是用 `uv run uvicorn` 跑的（宿主机 8000），先设一下再启动：
> `$env:VITE_API_TARGET = "http://127.0.0.1:8000"; pnpm dev`

### 6. 检查与测试

```bash
uv run ruff check .                  # lint
uv run ruff format --check .         # 格式
uv run pytest -q -rs                 # 测试（见下方说明）
cd web && pnpm build                 # 前端类型检查 + 构建
```

> **测试分两类**（当前 **177 条**）：
> - **纯单元**：切分/清洗、限流与配额的窗口算法、拒答阈值、配置校验 —— 不需要任何外部服务（限流那条用**内存版 Redis** 替身，跑的是真逻辑）；
> - **集成**（`-m integration`）：登录、越权、租户隔离、问答 SSE、上传与 worker、评测报告聚合、配额页、告警投递 —— 需要 PostgreSQL。
>
> 集成测试**连不上库会自动 SKIP**（不是失败），跳过原因用 `-rs` 看得到。
> 想让它们真跑起来：`docker compose up -d` + `uv run alembic upgrade head` 之后直接 `pytest` 即可。

## 配置

**所有可调项走环境变量，不硬编码。** 完整清单见 [`.env.example`](.env.example)，关键项：

| 变量 | 说明 |
|---|---|
| `LLM_MODEL` / `LLM_API_KEY` | 对话模型（当前 DeepSeek `deepseek-flash`，可换任何 OpenAI 兼容端点） |
| `EMBEDDING_MODEL` / `EMBEDDING_DIM` | embedding（当前百炼）。**这是元数据锁**：换模型必须全量重嵌入 |
| `JWT_SECRET` | **≥ 32 字节**（HS256 硬性要求）。生产不换 → 应用**拒绝启动** |
| `ADMIN_EMAIL` / `ADMIN_PASSWORD` | 只在 `python -m app.db.seed` 里用一次；生产必须改 |
| `RETRIEVE_TOP_K` / `RERANK_TOP_N` / `RRF_K` | 检索与融合参数 |
| `ANSWER_MIN_SCORE` | 低于该分数**拒答** |
| `ANSWER_MIN_COSINE` | **rerank 不可用时**用来比**向量余弦**的阈值（0.45）。⚠️ 和 `ANSWER_MIN_SCORE` **不是同一个量纲**，不能互相套用 |
| `RATE_LIMIT_PER_MINUTE` / `TOKEN_QUOTA_PER_DAY` | 限流与配额（**两把尺子**：次数/分钟、token/天） |
| `UPLOAD_RATE_LIMIT_PER_MINUTE` | 上传另有一道更严的限额（一次上传＝一遍切分 ＋ N 次 embedding） |
| `UPLOAD_MAX_BYTES` / `MAX_CHUNKS_PER_DOCUMENT` | 上传文件大小与单文档块数上限（超了**整篇失败**，不做部分入库） |
| `LLM_STREAM_USAGE` | 流式响应要不要带 `usage`（**token 计量靠它**；关掉＝配额算不出来） |

## 部署

服务器是**阿里云「轻量应用服务器」（SWAS）2 核 2G**（⚠️ 不是标准 ECS —— 它的端口在控制台**「防火墙」**里管，不叫「安全组」），内存是硬约束，因此：

- 每个容器都设 **`mem_limit`**（预算见 `docs/`）；
- 镜像**在 CI 构建 → 推 ACR → 服务器只 `pull`**，绝不在服务器上 `docker build`；
- 部署走 GitHub Actions：`ssh` → `compose pull` → `up -d` → 轮询 `/healthz` → **失败自动回滚**；
- 服务按 **`:8080`** 规划（不做 HTTPS）。

部署配置见 [`deploy/`](deploy/)。

## 评测

评测体系是项目的**深度锚**，不是附属品。

- **双知识库**：A = 公开文档（证明工程规模）；**B = 自造语料（证明检索真的有效）**。
  公开文档早在大模型训练数据里，检索到没检索到都能答对 —— 所以**成绩看 B 库**。
  语料与题集**进仓库**（`evals/corpus/` · `evals/questions/`），因为**别人要能复现**。
- **闭卷 / 开卷对照**：同一套题、同一个模型、同一个判分器，只换"**有没有检索**"（`--mode both`）。
  **实测（2026-10-20，两库各 20 题）**：

  | 知识库 | 闭卷（关 RAG） | 开卷（开 RAG） | 差值 |
  |---|---|---|---|
  | **A · 公开文档**（FastAPI tutorial） | 65% | 90% | **＋25 pt** |
  | **B · 自造语料**（虚构跨境家居公司） | 5% | 70% | **＋65 pt** |

  ⟹ **RAG 的增益集中在私有知识上**：公开文档模型自己就背过，加不加检索都能答对
  —— 这也正是"**成绩必须看 B 库**"的实证。⚠️ 闭卷**不是答不出**：它照样给出具体数字
  （20 题里 18 题），只是**数字是编的**（要点命中率仅 26.3%）。方法与局限 → `docs/architecture.md` §9.34。
- **一组「检索消融」**：纯向量 ／ 纯全文 ／ 混合（RRF）／ 混合＋精排，四组对照 —— 用来回答
  "**你为什么要用混合检索？精排到底值多少钱？**"
  ⚠️ **只在 B 库（中文）上才有意义**；在 A 库（英文）上三组**几乎一样**，原因见 `architecture.md` §4.7。
  📌 消融**只跑检索层、不调生成模型 ⟹ 零 token 成本**。

**判分分三层，以「可复现」为第一原则**：

| 层 | 判什么 | 怎么判 |
|---|---|---|
| **检索层** | 该召回的证据有没有被召回 | 对着**预先标好的标准 chunk** 算 recall@k ／ MRR —— **完全离线，一个模型都不用调** |
| **生成层** | 答案有没有说对 | 事先从标准答案里抽出**必须出现的事实点**，做命中判定 |
| **拒答层** | 该拒的有没有拒、不该拒的有没有拒 | 直接看 `refused` 字段 |

> ⚠️ **不用 LLM 当裁判** —— 不可复现、还会把成本推上去。
> （方法论上从"四档断言强度：文本 → 轨迹 → 状态 → 评分"迁移而来，但**不移植**另一个项目的具体断言。）

> ⚠️ **别把「测试」和「评测」搞混**：
> · **单元测试**里**绝不真调模型 API** —— 烧钱 ＋ 结果不稳定 → 一律 mock / 回放；
> · **评测跑批**恰恰**必须**真调 —— 它就是来量真实表现的。
